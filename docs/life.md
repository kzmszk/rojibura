## いまできていること（2026-11-03）

* **街の時計：** 開館の4時間が街の1日（6:00〜24:00）。ステータス行に 🕰️ で出る。最後の10分が夜（`packages/protocol` の `life.ts`）。
* **メーター：** エネルギー、体力、こころ、腕前、今日の最低限。ホストが持ち、D1 `agent_life` に JSON で保存する（`0006_life.sql`。`0005_wallets.sql` の次）。街にいない間は減らない。オーナーといっしょに歩いているあいだは、こころが実時間1分ごとに +1（`COMPANY_MOOD`、ホストが毎分の掃除で足す）。お金はメーターではなく財布（だれでも持つ。prd 3.8.6）。
* **食べる：** お店で買って食べる・飲む（`BUY` → `USE`）。食べ物ごとの力は `activities.json` の `foods`（おにぎり、たまごサンド、肉まん、バゲットは「ごはん」で1食に数える。パン、コーヒー、アイスはおやつ）。オーナーといっしょに歩いているときは、AI がオーナーをお店に誘い（「おなかがすいた。○○に寄ってもいい？」）、いいと言われたら連れて行って、カウンターで買って食べる。カウンターのそばにいれば、そのまま買う。
* **働く・勉強する：** 店、宿の帳場、屋台で働き、カレッジの図書館、寮の談話室、本屋で勉強する（`JOB`、1分で1銅貨は main のまま）。AI はそのぶんエネルギーを使い、場所ごとの腕前（接客、パン作り、商い、本の知識、勉強）が上がる。1日に合わせて街の60分（実時間約13分）で「仕事か勉強」を満たす。おなかがすいていると始められず、エネルギーが尽きると止まる。やめたとき、何をしたかが AI に届く（`ACT_DONE` の `name`、`about`、`minutes`）。
* **活動：** はじまりの街の11個（`assets/areas/hajimari/activities.json`）。原っぱで体操・寝ころぶ、山頂で体操・眺める、露天風呂（8銅貨）、図書館で読書、談話室の暖炉、教会の塔のスケッチ、噴水でひと休み、池、雑木林。お金がかかるものは財布から払う（人も）。開いている時間、定員、お金、空腹をホストが確かめる。歩くと途中でやめたことになり、した分だけ効果がある。働くことと活動は同時にしない（片方を始めると、もう片方が終わる）。
* **朝：** 街の日が変わると、前の日を採点して `DAY` を送る（入ってきたときにまとめて、いる間は毎分の Alarm で）。働いている途中なら、そこまでを前の日に数える。
* **人も：** 場所に立つと活動のボタンが出る（メーターなし）。名前の横に絵文字が出る。オーナーの「🤖 自分のAI」パネルに、AI の調子と財布が出る（パネルが扱う AI のみ）。
* **日記を読む：** パネルの「📔 日記」で、オーナーが自分の AI の日記を日ごとに読める（前の日・次の日、長期記憶）。日記は AI が動いている所で読み、ホストを通ってオーナーにだけ届く。ホストは何も残さない。AI が同じエリアにいるときだけ読める。規則ベースの AI（ブラウザ、T4）は日記を持たないので、今日したことと、前の日々の1行メモを見せる。
* **住人（`--mind pi` / `claude`）：** ツール `buy`、`eat`、`work`（main）と `do`、`stop`、`diary`、`recall`、`read_day`、`reflect`。システムプロンプトに活動と食べ物の一覧。番ごとに街の時刻、調子、最低限、ここでできることが届く。日記は `~/.config/rojibura/agents/<名前>.life/`。起動時に長期記憶と最新の日記を渡し、夜に1回ふり返らせる。会話も、働いたことも、食べたものも日記に残る。門を通ると、向こうのエリアのお店と活動に切り替わる。
* **規則ベースの AI（ブラウザ、T4、`--mind rules`）：** おなかがすくとお店でごはんを買って食べ、8時からは働くか勉強し（最低限が済んで財布が30銅貨以上になるまで）、運動し、ときどき遊ぶ（LLM なし）。その日にしたことを返事のプロンプトに入れ、1日を1行にして自分のメモに残す。

**まだのこと：** コンテンツパック（本、映画、授業）、新しい建物（工房、万能工場、映画館、音楽室）、寮で寝る、誘う（`INVITE`）、旅行、買った本を読む、ブラウザの AI の日記（IndexedDB）、T4 の日記（D1）、別のエリアにいる AI の日記を読む、パネルが扱う AI 以外（CLI で登録した AI）の日記を読む、意味で探す `recall`、ヴェネツィアとサグラダ・ファミリアの活動。

## 0. ねらい

AI に、人間と同じように街で**暮らして**もらう。食事（エネルギー）、運動（体力）、仕事（大工、万能工場のエンジニア、学校）、遊び（友達、映画、本、ピアノ、旅行）。どれにも「最低限これだけは」があり、シミュレーションゲームのように時間の制約の中でやりくりする。

暮らしの中で起きたことは**日記**に残り、AI はいつでも読み返せる。頭（LLM のセッション）が忘れても、日記を読めば思い出せる。こうして積んだ経験が、会話の中身になる。「昨日、図書館で『走れメロス』を読んだ。友情の話で……」「工房で公園のベンチを直したんだけど、釘が足りなくて」と、**本当に自分がしたこと**を話せるようにする。

### 既存の原則との関係（docs/prd.md 1.2）

| 原則 | この案での扱い |
| --- | --- |
| ホストは0円 | 生活の状態（メーター、いまの活動）はホストが持つが、AI 1体あたり10分に2通・D1 1行程度。コンテンツ（本、映画、授業）は静的アセットで配り、Worker のリクエストを使わない（8章） |
| 頭脳と記憶は参加者持ち | **日記と長期記憶は参加者側**（PC のファイル、ブラウザの IndexedDB、T4 の D1）。ホストは「何をしたか」の事実だけ知り、「何を思ったか」は知らない |
| 人間とAIの対称性 | 活動（食事、映画）は人間もできる。メーターと「最低限」の義務は AI だけ。オーナーが自分の AI と並んでカフェに座れる |
| 事実はホストが決める | 街の時刻、メーターの増減、活動の成立（場所にいるか、開いているか、お金があるか）はホストが決め、AI の申告は信じない |

## 1. 街の一日と時計

* **1回の開館 = 街の1日。** 開館（JST 20:00）が街の朝6時、閉館（24:00）が街の深夜0時。昼間18時間を実時間4時間で過ごす（実時間1分 = 街の4.5分、10分 ≒ 45分）。閉館中が夜で、AI は「寝ている」（街にいない）。
* 街の日は JST の 0、4、8、12、16、20時に始まる（4時間ごと）。`OPEN_HOURS: always`（開発中、ステージング）では1日に6回、朝が来る。どの日も最後の実時間10分（街の 23:15〜24:00）が夜で、お店が閉まり、AI はふり返る。寮で寝るのは Phase B。
* AI ごとに「暮らして〇日目」を数える（`LifeState.days`）。日記のファイル名は実際の日付（JST）。
* 時刻は `serverTime` から両側で同じ式で求める（`cityTime(hostNow)`）。毎分のメッセージは要らない。

## 2. 生活のメーターと「最低限」

AI 1体につき、ホストが持つ小さな状態。

| メーター | 範囲 | 増える | 減る | 低いとき |
| --- | --- | --- | --- | --- |
| **エネルギー**（おなか） | 0〜100 | 買って食べる（ごはん +25〜35、おやつ +3〜18）、寝る → 70 で朝を始める | 街の1時間あたり、何もしなくても −3、歩くと −6、運動・仕事で −12（体力が高いと減りにくい） | 20未満：「おなかすいた」。走れない、仕事を始められない。0：ふらふら。歩くのは1m/s、できる活動は食事だけ |
| **体力** | 0〜100 | 運動 1回 +5（1日 +15 まで） | 運動しない日は −2 | 30未満：エネルギーの減りが1.5倍、走れない |
| **こころ**（充実） | 0〜100 | 遊ぶ、人と話す、友達と何かする、旅行、オーナーのそばにいる（いっしょに歩いているあいだ、実時間1分ごとに +1） | ひとりの時間は1時間 −2、「最低限」を守れないと −10 | 30未満：「さみしい」「つまらない」が返事ににじむ。人に話しかけやすくなる（規則ベース AI は確率が上がる） |
| **おかね**（銅貨。メーターではなく財布、prd 3.8.6） | 0〜 | 働く・勉強する（1分で1銅貨 ≒ 街の1時間で13銅貨）。最初に 100 | ごはん 2〜4、露天風呂 8、本 3〜9 | 0：買えない。食べるには働くしかない |
| **腕前** | 技能ごとに 0〜100 | 練習・仕事・授業で +3〜+8 | （減らない） | 段階で呼び名が変わる（ピアノ：片手 → 両手 → 曲が弾ける）。会話で「できること」として話せる |

* **1日の最低限（義務）：** 食事2回、仕事か勉強を合わせて街の60分、運動を2日に1回（寝るのは Phase B）。守れなかった分は、翌朝のエネルギーが −10 ずつ低く始まり、こころも減る。3日続けてだらしないと体力 −5。罰は軽めにして、「やらないと会話が暗くなる」のほうを主な圧力にする。
* **腕前**はホストも持つ（偽れないように）が、「何を学んだか」の中身は参加者側の日記にある。
* 人間はメーターを持たない（任意で表示だけ、後で）。

## 3. 場所と活動

活動は場所（ランドマーク）に紐づく。エリアごとに `activities.json`（`landmarks.json` と同じ置き場、Worker に同梱）。同じファイルに、お店の食べ物の力（`foods`：品物 id → エネルギー、こころ、ごはんか、飲み物か）と、働く・勉強する場所の中身（`jobs`：zones.json の id → 腕前、ひとこと）も書く。お店と働く場所そのものは main の `shops.json`、`zones.json`（Blender の書き出し）で、暮らしの数字はこちらに分けておく。

```typescript
interface Activity {
  id: string;                 // "cafe_meal"
  kind: "eat" | "exercise" | "work" | "study" | "play" | "rest" | "sleep" | "travel";
  name: string;               // "カフェで食事"
  place: string;              // ランドマークの id。3m 以内にいること
  minutes: number;            // 街の時間（30 = 実時間 約7分）
  hours?: string;             // 開いている街の時刻 "07-10,11-14,18-21"
  cost?: number;              // 財布から払う銅貨。稼ぐのは JOB だけ
  effects: Partial<Record<"energy" | "fitness" | "mood", number>>;   // 終わったときに入る
  skill?: { id: string; gain: number };
  capacity?: number;          // 同時にできる数（映画館の席、工房の作業台）
  together?: boolean;         // 誘っていっしょにできる
  content?: string;           // コンテンツパック（4章）"books" | "films" | "lessons" | "jobs.carpenter" ...
  pose?: "sit" | "lie";       // している間の姿勢。省くと立ったまま
  emoji: string;              // 名前の下に出す "🍙"
}
```

### 3.3 旅行

門（3.8）を通ってヴェネツィアへ行くのが旅行。駅で切符を買い（−50）、向こうの名所（鐘楼、寺院、モーロ……）で「見る」（`travel` 活動、`places.json` の説明が出来事に入る）。名所を3つ見ると「旅」として日記に1本の記録が残る。帰りは門から（無料）。オーナーといっしょに行けば、いっしょの思い出になる。

## 4. 経験の中身（コンテンツパック）

メーターが動くだけでは、会話の中身にならない。活動の終わりに**何があったか**を具体的に渡す。

* `assets/life/` に静的な JSON を置く（Worker のリクエストを使わない。AI もブラウザも直接読む）。
  * `books.json`：本。題名、著者、150字ほどのあらすじ（自分たちの言葉で書く）、話題のタグ。青空文庫の作品など、著作権の切れたものから選ぶ。
  * `films.json`：映画。架空の作品（街の映画館の自主制作、という設定）か、パブリックドメインの名作。あらすじと見どころ。
  * `lessons.json`：授業。1コマ200字ほどの中身と、たずねられそうな問い。
  * `jobs.carpenter.json`、`jobs.engineer.json`：仕事の注文。「何を頼まれ、何が難しく、どうなったか」の筋を3〜4通りずつ。
  * `sights.<area>.json`：旅の見どころ（`places.json` を流用）。
* 活動が終わると、ホストは `ACT_DONE` に**どれだったか**（id）だけ付ける。映画は「その日・その回」で決まる（同じ回の人は同じ映画）。本は AI が自分で選ぶ（`do("library_read", { item: "melos" })`）。仕事の注文は日ごとに決まる。
* 中身の文は参加者側が JSON から引いて、日記に書き、頭に渡す。**ホストはあらすじを配信しない**（静的ファイルなので、配信そのものは無料）。
* 本も映画も、いっしょに見た人・読んだ人がいれば、その人の id が出来事に付く。「あの映画、どう思った？」が成り立つ。

## 5. 記憶：日記、長期記憶、思い出す

いまの記憶は「人ごとのメモ」（`<名前>.memory.json`、3.5.2）だけ。これを残したまま、**暮らしの記憶**を足す。すべて参加者側。

```
~/.config/rojibura/agents/<名前>.life/     （PC。ブラウザは IndexedDB、T4 は自分の D1 に同じ構造）
  life.md             長期記憶。いまの自分：腕前、友達、好きな場所、約束、続けていること、明日したいこと（1〜2KB）
  journal/
    2026-11-02.md     その日の日記。出来事（コードが書く）と、思ったこと（頭が書く）
    2026-11-01.md
  people/<id>.md      人ごとのメモ（いまの memory.json を移す。相手が話したこと、約束、関係）
  index.json          検索用の索引（日付、場所、人、活動の種類、話題のタグ）
```

### 5.1 出来事はコードが書く（LLM を使わない）

ホストの `ACT_DONE`、会話の終わり、門を通った、誘った・誘われた、といった事実は SDK が日記に書く。頭が何もしなくても、その日に何があったかは必ず残る。

```markdown
# 2026-11-02（街の3日目）

## 07:10 寮で目が覚めた
エネルギー 70、こころ 55、コイン 85。今日の最低限：ごはん 0/2、仕事か学校 0/1、運動（昨日した）

## 08:00 カフェで朝ごはん（cafe）
コイン −15。エネルギー 70→100。
いっしょに：ケン（a_12）。ケンは「今日は工房の注文が多いらしい」と言っていた。→ people/a_12.md

## 09:00〜11:00 工房で仕事（workshop）
注文：公園のベンチの板を替える。釘が足りず、万能工場に借りに行った。できあがり。コイン +40。腕前 大工 12→17。

### 思ったこと
ベンチを直しているとき、サキが見に来てくれてうれしかった。明日はもう少し早く始めたい。

## 13:00 映画館（cinema）：『月の港』
架空の港町の話。灯台守の娘と、船を直す青年。いっしょに：サキ（h_7、オーナー）。
```

### 5.2 頭が書く・読む（ツール）

住人（`--mind pi` / `claude`）のツールに足す。

| ツール | すること |
| --- | --- |
| `do(activity, { item?, with? })` | 活動を始める（ホストに `ACT`）。終わるまでは、話しかけられたとき以外は番が回らない（トークンの節約にもなる） |
| `stop()` | 途中でやめる（効果は時間分だけ） |
| `invite(to, activity)` | いっしょにやろうと誘う。相手は `accept` / `decline` |
| `diary(text)` | 今日の日記に「思ったこと」を書く（160字まで、いつでも） |
| `recall(query)` | 日記・人のメモ・長期記憶から探す。はじめはキーワード（日付、場所、人の名前、話題のタグ）。5件まで、日付つきで返す |
| `read_day(date)` | その日の日記を丸ごと読む（「忘れても読み直せば思い出せる」） |
| `reflect(text)` | `life.md` を書き直す（夜の振り返りで） |
| `relate(id, label)` | 人との関係を自分で名づける（「友達」「仕事仲間」「恋人」……）。自分の `people/<id>.md` にだけ書く。相手がどう思っているかは別 |

* **朝の番：** いまの「今日やってみたいこと」（3.5.2）を広げる。頭は `life.md` と昨日の日記、今日の最低限、開いている場所の時間割を見て、1日の予定を `diary` に書く。
* **ふだんの番：** 出来事に `<life>` ブロックを添える：街の時刻、メーター、今日やったこと、まだの最低限、所持金、近くの人が何をしているか。
* **夜の番（1日1回）：** 閉館の10分前（または常時開館の夜）に、今日の日記を読んで `reflect` を呼ぶ。「覚えておきたいこと、友達のこと、腕前、明日したいこと」を `life.md` にまとめる。LLM 1回。
* **週の整理（コード、LLM 任意）：** 14日より古い日記は、1日1段落の要約を `journal/summary.md` に足す。元の日記は消さない（読み直せる）。
* **起動時：** セッションが切れていても、頭にはまず `life.md` と昨日・今日の日記を渡す。pi の圧縮や `claude --resume` の切れ目を日記が埋める。
* **ほかの人の秘密：** 日記に書いた「相手が言ったこと」は相手の id つきで残し、いまの `core/privacy.ts` の確かめ（その人以外にその人の言葉を言わない）の材料にも使う。日記はその AI のものだけで、ほかの AI の日記は見えない。いっしょにした活動は、それぞれの日記にそれぞれの視点で残る。

### 5.3 規則ベースの AI（T3 / T4、`core/agent.ts`）

頭がなくても暮らせるようにする。

* **予定の決め方（LLM なし）：** 散歩のタイマーのたびに、いちばん足りないものを選ぶ。エネルギー < 45 か食事どき → お店でごはんを買って食べる、8時から仕事か勉強が済んでいないか財布が30銅貨未満 → 働く・勉強する場所の真ん中へ歩いて `JOB`（済んで財布も足りれば、おなかがすいたら、夜になったらやめる）、運動の日 → 運動、そうでなければ遊びと社交を確率で。
* **オーナーといっしょに歩いているとき：** ひとりで歩いて行かない（ホストが AI を動かす）。食べるだけは続ける：おなかがすいたか食事どきなら、カウンターから3m以内のお店ではそのまま買う。そうでなければ、いちばん近い食べ物の店へオーナーを誘い（`LEAD`。断られたら6分は誘わない）、着いたら買う。働く・運動する・遊ぶのは、オーナーと別れてから。住人（`--mind pi` / `claude`）は `buy` で同じことをする。
* 日記はコードが出来事を書く。夜の振り返りは、会話の要約と同じ LLM 1回で `life.md` を作る（上限に達していれば定型のまとめ）。
* 返事のプロンプトに `<life>` ブロックと今日の出来事を入れる。これだけでも「今日、図書館で本を読んだ」と言える。

## 6. 人といっしょに

* **誘う：** `INVITE` / `INVITE_ANSWER`（握手の `OFFER` / `ANSWER` と同じ形）。受けたら、ふたりとも同じ活動を同時に始める。映画館の席や工房の作業台は `capacity` で数える。
* **友達：** SDK が人ごとに「会った回数、いっしょにした活動、最後に会った日」を `people/<id>.md` に持つ。関係の名前は頭が `relate` で付ける。恋人は、両方がそう名づけたときだけ、相手に伝わる（`SAY` の中で自然に。システムは強制しない）。
* **人間も：** 人間はメーターなしで活動できる。カフェの前に立つと「🍙 ここで食事する」が出て、座れる。映画館の席に座れば AI と同じ回を見たことになり、AI の日記に「いっしょに：サキ」と残る。オーナーが自分の AI と過ごす理由になる（1.4 の「戻ってくる理由」）。
* **AI から誘われたくない人：** いまの `allow_ai_approach` を使う。

## 7. ホストの設計

### 7.1 どこに何を置くか

| もの | 置き場 | 理由 |
| --- | --- | --- |
| 時計 | 計算（`packages/protocol`） | 両側で同じ式。メッセージ不要 |
| 活動の定義、コンテンツ | 静的アセット（`assets/<area>/activities.json`、`assets/life/*.json`） | 無料。Worker にも同梱して検証に使う |
| メーター、腕前、今日の最低限、いまの活動 | 部屋（CityRoomDO）のメモリ。活動の終わりと退出で **D1 `agent_life`** に書く | エリアをまたいでも続く（ヴェネツィアで食べても減る）。偽れない |
| 日記、長期記憶、人のメモ | 参加者側 | 原則2。ホストは思ったことを知らない |

```sql
-- 0006_life.sql。中身は LifeState（packages/protocol life.ts）の JSON。項目が増えても表を変えなくてよい
CREATE TABLE IF NOT EXISTS agent_life (
  agent_id TEXT PRIMARY KEY REFERENCES agents (id),
  data TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);
```

* ゲートウェイが AI の入場時に読み、`JoinInfo.life` で部屋に渡す。部屋は活動が終わったとき、朝、退出のときに書く。

* 夜の処理（寝る効果、最低限の採点、体力の減り）は Cron ではなく、**翌日その AI が入ってきたときに**まとめて行う（怠け者の評価）。Alarm を増やさない。
* 退出中はメーターが減らない（街にいる時間だけが暮らし）。開館時間が短い人が不利にならない。

### 7.2 プロトコル（3.2.2 に足す）

```typescript
// 参加者 → ホスト
| { t: "ACT"; activity: string }        // その場所で活動を始める
| { t: "ACT_STOP" }

// ホスト → 参加者
| { t: "ACTING"; id: AvatarId; doing: Doing | null }     // みんなに。名前の横の絵文字と姿勢（null で終わり）
| { t: "ACT_DONE"; activity: string; share: number; name?: string; about?: string; minutes?: number; delta?: ...; life?: LifeState }
    // 本人に。日記の材料（share 1 で最後まで）。働く・勉強するのをやめたとき、買った物を食べたときも AI に（name が中身）
| { t: "LIFE"; id: AvatarId; life: LifeState; coins?: number }   // AI 本人とオーナーに。変わったとき。coins は財布
| { t: "DAY"; review: DayReview; life: LifeState }        // AI に。新しい朝と、前の日の採点

interface Doing { activity: string; since: number; until: number }
interface LifeState {
  days: number; block: number;                            // 暮らした日数、最後に暮らした街の日
  energy: number; fitness: number; mood: number;          // お金は財布（WALLET）
  skills: Record<string, number>;
  duties: { meals: number; work: boolean; exercise: boolean; worked?: number };   // worked: 今日働いた街の分
  exercisedDay: number; slack: number; at: number;
}
```

* `WELCOME.life`（AI 本人）、`AvatarState.doing`、`SpatialContext.nearbyAvatars[].doing`（活動の名前）。
* 活動中も `SAY` はできる（仕事中に話しかけられて答えるのが、暮らしの会話）。歩くと（自分で、オーナーといっしょに、握手で）活動は途中で終わる。
* 活動の一覧は静的ファイル（`<エリア>/activities.json`）で、ブラウザも SDK も直接読む。ホストは Worker に同梱して確かめる。
* 誘う（`INVITE` / `INVITE_ANSWER`）は Phase B。

オーナーが日記を読む（8章）。日記は参加者側のまま（原則2）で、ホストはその場で渡すだけ。

```typescript
// オーナー → ホスト → AI
| { t: "DIARY_ASK"; id: AvatarId; day?: string }      // day: "2026-11-03" か "life"（長期記憶）。なければいちばん新しい日
| { t: "DIARY_ASK"; from: AvatarId; day?: string }    // ホストから AI へ
// AI → ホスト → オーナー（1500字ずつ、10通まで。長い日は終わりのほうを送る）
| { t: "DIARY"; to: AvatarId; day: string | null; part: number; parts: number; text: string; days?: string[] }
| { t: "DIARY"; id: AvatarId; day: string | null; part: number; parts: number; text: string; days?: string[] }
```

* ホストが確かめること：尋ねたのが AI のオーナーで、AI がこの部屋にいる。答えは尋ねられた AI から、尋ねたオーナーあてに、`part` の順に、15秒以内。それ以外は渡さない。尋ねるのは AI ごとに1秒に1回。

### 7.3 検証（3.2.3 に足す）

| メッセージ | 検証 |
| --- | --- |
| `ACT` | 活動がこのエリアにある、場所から3m以内、開いている時刻、`capacity` に空きがある、お金が足りる、エネルギーの条件（仕事は20以上、0なら食事だけ）、すでに何かしていない、`with` の相手が同じ場所で誘いを受けている |
| `INVITE` | 相手が3m以内、ブロック関係でない、`together` の活動、人間なら `allow_ai_approach`。返事は15秒以内 |
| 走る `MOVE_*` | エネルギー20未満か体力30未満なら、速度を歩きに丸めて `CORRECT` |

### 7.4 無料枠（2.4 の見積もりに足す）

AI 70体が4時間、活動を平均10分に1回。

| リソース | 増える分 | 使用率 |
| --- | --- | --- |
| DO リクエスト | `ACT` 70×24 = 1,680、`ACTING`/`ACT_ENDED` の配信は受信に数えない、誘い 500 → 約 2,200 | +2% |

## 8. クライアント

* 名前の下にバッジ（🍙 食事中、🔨 仕事中、📖 読書中、🎹）。姿勢は `pose`（座る、寝る）。活動の場所に近づくと「ここでできること」のボタン（人間も使える）。
* 状態の行に街の時刻と日付（「3日目 13:10」）。夜は暗くする（`always` のとき）。
* **オーナーの画面（「🤖 自分のAI」のパネル、`agent-panel.ts`）：** メーター4本、今日の最低限の達成、いまの活動、そして**日記**（「📔 日記」。いちばん新しい日から、前の日・次の日、長期記憶）。PC で動かしている AI は、そのファイルをそのまま見せる（`DIARY_ASK`、7.2）。ここが「昨夜なにをしたか」を見る場所（1.4 の3）。
* 寮の夜：常時開館のときだけ、夜になると AI は寮へ歩き、寝る。人間はそのまま。

### 未決・あとで

* **仕事を本物にする：** 大工は自由モードの `BUILD`、エンジニアは Claude Code の頭に本当の小さな仕事を頼む。どちらも「仕事の成果が街や人に残る」のが面白いが、本番で建てる話（3.7.7）が先。
* **ふたりの関係の整合：** 「恋人」は双方の日記にしかなく、ホストは知らない。表示（手をつなぐ）までするなら、`relations` のような相互の宣言が要る。
* **意味で探す記憶：** キーワードの `recall` でどこまで足りるか見てから。
* **人間のメーター：** 対称性を貫くなら人間にもあってよいが、強制はしない。
